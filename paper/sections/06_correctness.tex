\section{Mechanized Correctness in Lean 4}
\label{sec:correctness}

Compiler correctness is paramount when applying aggressive global transformations. NumLang is the first supercompiler whose end-to-end semantic preservation and termination theorems are completely formalized and machine-checked in the \textbf{Lean 4} interactive theorem prover (Phase 38).

\subsection{Proof Architecture}
The formal proof codebase is structured modularly in \texttt{lean/Supercompiler/}, comprising 10 verified modules totaling over 3,200 lines of Lean 4 definitions and proofs:
\begin{itemize}
    \item \texttt{AST.lean}: Formal inductive syntax of SSA Mid-Level IR, basic blocks, instructions, terminators, and expressions.
    \item \texttt{Semantics.lean}: Big-step operational semantics $(p, \sigma) \Downarrow v$ defining configuration transitions and heap updates.
    \item \texttt{Whistle.lean}: Homeomorphic embedding relation $\trianglelefteq$ and size-bounded filtering lemmas.
    \item \texttt{Generalize.lean}: Soundness of Most Specific Generalization (MSG) and state anti-unification.
    \item \texttt{Distillation.lean}: Soundness of global process-tree folding across distinct function boundaries.
    \item \texttt{MRSC.lean}: Soundness of configuration hypergraph expansion and Pareto-optimal lattice extraction.
    \item \texttt{Refinement.lean}: Soundness of interval-based path-sensitive branch pruning and bounds check removal.
    \item \texttt{Compaction.lean}: Soundness of dead-node elimination, $\eta$-reduction, and copy propagation.
    \item \texttt{Termination.lean}: Mechanization of Kruskal's Tree Theorem and guaranteed termination of driving.
    \item \texttt{Main.lean}: The top-level composition theorem linking all transformation passes.
\end{itemize}

\subsection{Main Correctness Theorem}
The central verification result establishes full observational equivalence between the input program and the supercompiled residual program:

\begin{theorem}[End-to-End Semantic Soundness (\texttt{supercompiler\_sound})]
\label{thm:soundness}
For any well-typed NumLang program $p$, initial execution state $\sigma$, and resulting value $v$:
\begin{equation}
(p, \sigma) \Downarrow v \iff (\text{supercompile}(p), \sigma) \Downarrow v
\end{equation}
\end{theorem}

\begin{proof}[Proof Sketch]
The proof proceeds by forward and backward simulation induction over the process-tree driving steps. 
\begin{enumerate}
    \item \textbf{Driving Step Simulation}: Each symbolic driving rule (assignment evaluation, branch splitting, heap allocation) preserves the operational valuation under all concretizations $\rho \models \Pi$.
    \item \textbf{Knot Tying \& Folding}: When a knot edge connects node $N_j$ to ancestor $N_i$, state remapping lemma (\texttt{fold\_sound}) establishes that evaluation along the cyclic residual basic block matches the fixpoint of the original loop.
    \item \textbf{Generalization}: The anti-unification lemma (\texttt{generalize\_sound}) proves that abstracting divergent subterms into fresh registers introduces no spurious behaviors.
    \item \textbf{Compaction \& Refinement}: Dead configuration pruning and bounds-check removal lemmas (\texttt{compaction\_sound}, \texttt{refinement\_sound}) guarantee that deleted instructions had no observable semantic side effects.
\end{enumerate}
Composing these inductive lemmas in \texttt{Main.lean} yields the bidirectional equivalence $(p, \sigma) \Downarrow v \iff (\text{supercompile}(p), \sigma) \Downarrow v$.
\end{proof}
