# Plan 10-01: Scalar Replacement of Aggregates (SROA) & SSA Register Promotion

**Phase:** 10 — Scalar Replacement of Aggregates (SROA) & SSA Register Promotion
**Requirements:** SROA-01, SROA-02, SROA-03
**Status:** Completed

## Objective

Implement Scalar Replacement of Aggregates (SROA) in the Cranelift code generation backend. For all small fixed arrays (`N <= 16`), replace stack-allocated slots with individual Cranelift SSA variables (`Variable`). Lower array indexing, assignments, and vector operations (`dot`, `sum`, `vec_add`) directly onto SSA register variables, eliminating hundreds of millions of stack loads and stores in tight numerical kernels.

## Proposed Changes

### Cranelift Backend (`src/codegen/cranelift_backend.rs`)
1. **Extend `Storage`**:
   - Add `Storage::PromotedArray { vars: Vec<Variable>, len: usize, elem_ty: Type }`.
   - Small arrays (`len <= 16`) allocate `Storage::PromotedArray` with individual Cranelift variables instead of stack slots.
2. **Promoted Array Declaration & Assignment**:
   - `TypedStmt::Let`: For arrays with `len <= 16`, declare Cranelift SSA variables for each element and define them with initial values.
   - `TypedStmt::Assign`: Handle whole-array assignment between promoted arrays or from vector intrinsics by copying/updating SSA variables.
3. **Element Reads & Writes**:
   - `TypedExpr::Index`: For constant index `c`, lower to `builder.use_var(vars[c])`. For dynamic index, use a tree of `builder.ins().select` (CMOV) across the promoted variables.
   - `TypedStmt::IndexAssign`: For constant index `c`, lower to `builder.def_var(vars[c], new_val)`. For dynamic index, update each variable using `select`.
4. **Register-Promoted Vector Intrinsics**:
   - Update `dot`, `vec_add`, `sum` in `cranelift_backend.rs`:
     - When arguments are `PromotedArray`, read elements directly via `builder.use_var` without `stack_addr` or `load`.
     - Perform unrolled FMA or arithmetic directly on SSA values.
     - For `vec_add`, define the destination SSA variables directly.
