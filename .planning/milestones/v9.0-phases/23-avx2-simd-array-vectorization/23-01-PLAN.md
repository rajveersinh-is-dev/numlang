# Plan 23-01: AVX2 SIMD Array Vectorization

**Phase:** 23 — AVX2 SIMD Array Vectorization
**Requirements:** SIMD-01
**Status:** In Progress

## Objective

Accelerate multi-element array sweeps, memory copies, and vector kernels using SIMD vector instructions in the Cranelift backend and harmonize the Rule 110 cellular automaton benchmark to use native bitwise operations, dropping runtime into competitive microsecond speeds matching and beating C and Rust.

## Proposed Changes

### 1. Vectorized Array Copying & Memory Operations (`src/codegen/cranelift_backend.rs`)
- In `translate_stmt`:
  - For array assignments (`dst_slot = src_slot`), replace element-by-element scalar loads and stores with 128-bit vector chunk copying using `types::I8X16` (16 bytes per chunk).
  - Unroll 4-way for large arrays (64 bytes per unrolled step) to maximize load/store port throughput and reduce loop branches.
  - Handle remaining bytes (< 16 bytes) with scalar loads/stores.
  - Ensure array stack slots are aligned to at least 16 bytes (`align = 4`, $2^4 = 16$).

### 2. SIMD Vector Arithmetic for Array Kernels (`src/codegen/cranelift_backend.rs`)
- In `translate_vec_add_into_slot`:
  - Detect element type and vector capacity:
    - `i64`: use `types::I64X2` vector additions (2 elements per vector).
    - `f64`: use `types::F64X2` vector additions (2 elements per vector).
    - `i32`: use `types::I32X4` vector additions (4 elements per vector).
    - `f32`: use `types::F32X4` vector additions (4 elements per vector).
  - Loop with vector step, followed by cleanup scalar loop for remainder elements.

### 3. Rule 110 Cellular Automaton Optimization (`tests/multi_language_benchmarks.rs`)
- Update Rule 110 in `tests/multi_language_benchmarks.rs` to utilize native bitwise operators (`&`, `|`, `^`, `<<`, `>>`) with popcount, matching the parity of C and Rust implementations.
- Verify expected exit code (38) and measure runtime reduction from ~6ms to microseconds.

### 4. Verification & Testing (`tests/simd_feature_tests.rs`)
- Add integration tests verifying:
  - Vectorized array assignment / copying on `[i64; 64]` and `[f64; 32]`.
  - Vectorized `vec_add` on `[i64; 32]` and `[f64; 16]`.
  - Native bitwise Rule 110 execution producing exact expected state.
