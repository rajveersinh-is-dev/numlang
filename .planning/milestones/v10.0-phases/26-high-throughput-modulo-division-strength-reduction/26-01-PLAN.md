# Plan 26-01: High-Throughput Modulo & Division Strength Reduction

**Phase:** 26 — High-Throughput Modulo & Division Strength Reduction
**Requirements:** DIV-01, DIV-02
**Status:** In Progress

## Objective

Eliminate multi-instruction sign-bias arithmetic and hardware division stalls for modulo and division operations. Implement static non-negative range propagation across functions so that non-negative dividends (`state`, `i`, `count`, etc.) lower:
1. Power-of-two modulo `x % (1 << k)` to a single-instruction bitwise AND (`x & ((1 << k) - 1)`).
2. Power-of-two division `x / (1 << k)` to a single-instruction logical shift (`x >> k`).
3. Arbitrary constant modulo `x % d` and division `x / d` to high-throughput unsigned reciprocal multiplication (`umulhi`), eliminating `add_indicator`, sign bit extraction, and signed arithmetic fixups.
4. General signed power-of-two modulo to direct branchless mask subtraction (`n - ((n + bias) & -d)`), saving cycles over quotient-reconstruction.

## Proposed Changes

### Cranelift Codegen Backend
#### [MODIFY] `src/codegen/cranelift_backend.rs`
- Add `compute_magic_u64_nonneg(d: u64) -> Option<(u64, u8)>`:
  - Implements the Granlund-Montgomery unsigned multiplier search for $0 \le x < 2^{63}$, finding $(M, s)$ such that $\lfloor (x \times M) >> (64 + s) \rfloor = \lfloor x / d \rfloor$.
- Add static non-negative analysis helpers:
  - `collect_known_non_negative_vars(body: &TypedBlock) -> HashSet<String>`: Runs iterative fixed-point analysis to discover all local variables whose initializations and mutations are non-negative.
  - `is_expr_known_non_negative(expr: &TypedExpr, non_negative_vars: &HashSet<String>) -> bool`: Recognizes literals $\ge 0$, variables in `non_negative_vars`, non-negative additions/multiplications, modulo with positive divisors, logical/arithmetic right shifts of non-negative values, bitwise AND with positive masks, and intrinsics like `abs` and `sqrt`.
- Store `known_non_negative_vars: HashSet<String>` in `FunctionTranslationState`.
- In `FunctionTranslationState::emit_fast_signed_div`:
  - If `is_nonneg` and $d > 0$:
    - If $d$ is a power of 2 ($d = 1 \ll k$): lower directly to `builder.ins().ushr_imm_s(n, k as i64)`.
    - If $d$ has non-negative magic $(M, s)$: lower to `umulhi` + optional `ushr_imm_s(q, s)`.
- In `FunctionTranslationState::emit_fast_signed_rem`:
  - If `is_nonneg` and $d > 0$:
    - If $d$ is a power of 2 ($d = 1 \ll k$): lower directly to `builder.ins().band_imm_s(n, (d - 1) as i64)`.
    - If $d$ has non-negative magic $(M, s)$: compute quotient via `umulhi` + optional `ushr_imm_s(q, s)`, then `rem = n - q * d`.
  - If signed power-of-two modulo:
    - Lower to `n - ((n + bias) & -d)` directly using `band_imm_s`.
