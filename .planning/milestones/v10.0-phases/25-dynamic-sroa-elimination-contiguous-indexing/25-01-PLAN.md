# Plan 25-01: Dynamic SROA Elimination & Contiguous Indexing

**Phase:** 25 — Dynamic SROA Elimination & Contiguous Indexing
**Requirements:** SROA-01, SROA-02
**Status:** Pending

## Objective

Restrict Scalar Replacement of Aggregates (SROA) in `src/codegen/cranelift_backend.rs` to purely statically indexed arrays. When an array is indexed dynamically (e.g. `arr[var]` or `arr[expr]` with a non-constant index), retain it as a contiguous stack slot (`Storage::Array`) rather than promoting to SSA variable arrays (`Storage::PromotedArray`). This eliminates the catastrophic `O(len)` CMOV select tree cascade on dynamic reads and writes, lowering dynamic lookups to single-cycle indexed memory operations (`mov rax, [rsp + rdi*8]`) and slashing hundreds of millions of instructions in N-Queens and search loops.

## Proposed Changes

### Cranelift Codegen Backend
#### [MODIFY] `src/codegen/cranelift_backend.rs`
- Add an AST pre-scan helper `collect_dynamically_indexed_arrays(body: &TypedBlock) -> HashSet<String>`:
  - Traverses all statements and expressions in a function.
  - Identifies array variables accessed via `TypedExpr::Index` where `index` is NOT a constant literal (`TypedExpr::Literal { lit: TypedLiteral::Int(..), .. }`).
  - Identifies array variables mutated via `TypedStmt::IndexAssign` where `index` is NOT a constant literal.
- In `compile_function`:
  - Run `collect_dynamically_indexed_arrays(&func.body)` and pass the resulting `HashSet<String>` to `FunctionTranslationState`.
- In `FunctionTranslationState::translate_stmt` for `TypedStmt::Let`:
  - If `ty` is `Type::Array(elem, len)` where `*len <= 16`:
    - Check if `self.dynamically_indexed_arrays.contains(name)`.
    - If `false` (purely statically indexed): allocate `Storage::PromotedArray` (CPU registers).
    - If `true` (dynamically indexed): allocate `Storage::Array` on the stack slot.
- Statically indexed arrays (`dot`, `vec_add`, `sum`, constant element indexing) continue to use register-promoted SSA variables with zero stack memory round-trips.
