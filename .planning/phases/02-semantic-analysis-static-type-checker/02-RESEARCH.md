## User Constraints (from CONTEXT.md)

- **Default literal inference:** Integer literals default to `i64` and float literals default to `f64` when unannotated (`let x = 42;`).
- **Strict type coercion:** No implicit conversions between types (e.g., `f64 + i64` rejected at compile time) to guarantee numerical precision and avoid silent performance penalties.
- **Variable shadowing:** Block-scoped variable shadowing permitted (nested blocks can re-bind names).
- **Immutability defaults:** Variable bindings are immutable by default.
</user_constraints>

<research_summary>
## Summary

Phase 2 builds the semantic analysis and static type checking layer of the `numlang` compiler. It takes the untyped AST generated by Phase 1, performs lexical symbol resolution, enforces variable immutability, checks function signatures, and validates strict type safety across all expressions and statements. The output is a verified Typed AST ready for IR code generation in Phase 3.

Key components required:
1. **Type System (`src/typecheck/types.rs`):**
   - Primitive numerical types: `i32`, `i64`, `f32`, `f64`.
   - Boolean type: `bool`.
   - Unit / void return type: `void`.
   - Conversion from AST type strings to `Type`.
2. **Symbol Table & Scoping (`src/typecheck/symtab.rs`):**
   - Stack-based lexical environment (`Vec<HashMap<String, Symbol>>`).
   - `Symbol` struct tracking identifier name, `Type`, mutability (`is_mutable: bool`), and declaration `Span`.
   - Scope push/pop semantics supporting block shadowing.
   - Global function symbol table tracking function signatures (`name`, `params: Vec<Type>`, `return_ty: Type`, `span: Span`).
3. **Parser Enhancements for Mutability & Reassignment:**
   - To support immutability enforcement, the grammar must recognize `let mut x = ...` and assignment statements `x = expr;`.
   - When assignment occurs to an immutable variable, the type checker rejects it with an explicit diagnostic.
4. **Type Checking Pass (`src/typecheck/checker.rs`):**
   - Traverses AST, infers/checks types.
   - Strict equality on binary operands (no implicit widening or float-int casting).
   - If/while condition must be `bool`.
   - Returns must match enclosing function's declared return type.
5. **Diagnostics Integration (`src/diagnostic.rs`):**
   - Rich `miette` diagnostics with source spans, error codes, and help suggestions for type mismatches, undeclared variables, immutable reassignments, and arity mismatches.
</research_summary>

<architecture_patterns>
## Architecture Patterns

### Scope Stack Pattern
```rust
pub struct Symbol {
    pub name: String,
    pub ty: Type,
    pub is_mutable: bool,
    pub span: Span,
}

pub struct ScopeEnvironment {
    scopes: Vec<HashMap<String, Symbol>>,
}

impl ScopeEnvironment {
    pub fn enter_scope(&mut self) { self.scopes.push(HashMap::new()); }
    pub fn exit_scope(&mut self) { self.scopes.pop(); }
    pub fn define(&mut self, symbol: Symbol) -> Result<(), TypeError>;
    pub fn lookup(&self, name: &str) -> Option<&Symbol>;
}
```

### Strict Type Inference & Checking
- Literals: `Int(n)` -> `Type::I64`, `Float(f)` -> `Type::F64`, `Bool(b)` -> `Type::Bool`.
- If annotated: `let x: i32 = 10;`, the integer literal 10 conforms to `Type::I32`.
- Binary arithmetic (`+`, `-`, `*`, `/`, `%`, `^`): `left.ty == right.ty && left.ty.is_numeric()`.
- Relational comparisons (`<`, `<=`, `>`, `>=`): `left.ty == right.ty && left.ty.is_numeric()`, result is `Type::Bool`.
- Equality (`==`, `!=`): `left.ty == right.ty`, result is `Type::Bool`.
- Logical (`!`): operand must be `Type::Bool`.
</architecture_patterns>
