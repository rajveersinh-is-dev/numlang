<objective>
Implement 1D contiguous numeric arrays with runtime bounds checking, along with core math intrinsics and SIMD-friendly vector operations (abs, sqrt, dot product, element-wise addition, sum).

Purpose: Enable high-performance numerical and vector computations on bare metal without GC or dynamic allocation overhead.
Output: Array syntax, type checking, bounds-checked stack slot codegen, vector math intrinsics, and comprehensive test suite in `tests/array_math_tests.rs`.
</objective>

<execution_steps>
1. Add bracket tokens (`[`, `]`) and colon/semicolon support in array types if needed.
2. Extend AST with array types, array literal expressions, and indexing expressions (both for reading `arr[i]` and writing `arr[i] = val`).
3. Update parser to parse array types, array literals, and array index expressions.
4. Update type checker:
   - Type check array literals ensuring all elements match element type `T`.
   - Type check array indexing ensuring target is an array, index is integer (`i64` or `i32`), and resulting type is `T`.
   - Register built-in math and vector functions (`abs`, `sqrt`, `dot`, `vec_add`, `sum`).
5. Update Cranelift codegen:
   - Allocate fixed-size arrays in stack slots.
   - For `arr[i]`, emit an unsigned comparison bounds check `i < len`; if out-of-bounds, branch to exit block with code 101.
   - For `arr[i] = val`, emit bounds check and memory store.
   - Implement codegen or inlining for math intrinsics (`abs`, `sqrt`) and vector operations (`dot`, `vec_add`, `sum`).
6. Write integration tests in `tests/array_math_tests.rs` covering array creation, indexing, bounds checking panic/exit, and vector math execution.
</execution_steps>
