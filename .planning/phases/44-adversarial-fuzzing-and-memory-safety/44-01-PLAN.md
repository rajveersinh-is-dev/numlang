# Phase 44: Adversarial Fuzzing and Memory Safety — Plan

> **Phase**: 44  
> **Status**: Completed  
> **Traceability**: `ADVERSARIAL_AUDIT.md` §3.1  

## Objective
Provide safe, bounded heap memory allocation to prevent unbounded leaks on long-running loops, recursive data structures (`nrev`), and tree mutations (`tree_flip`). Implement an explicit scoped arena runtime for supercompiled loop iterations.

## Requirements
- **FUZZ-01**: Implement arena allocator runtime in `src/runtime/arena.rs` and `src/runtime/arena.c` with chunk management, peak tracking, and reset functions (`__nl_arena_create`, `__nl_arena_alloc`, `__nl_arena_reset`, `__nl_loop_reset`).
- **FUZZ-02**: Integrate arena fast-path into `src/codegen/cranelift/` and `src/codegen/cranelift_backend.rs` (`__nl_arena_cur`, `__nl_arena_end`).
- **FUZZ-03**: Implement loop escape analysis (`should_reset_loop_iteration`) in backend and `residualize.rs` to emit `__nl_loop_reset()` latch at loop back-edges for non-escaping allocations.
- **FUZZ-04**: Verify 50,000-iteration memory bounds and zero memory corruption in `tests/memory_leak_tests.rs`.

## Verification
- `cargo test --test memory_leak_tests` passes (6/6 tests).
- Peak memory consumption remains $O(1)$ across 50,000 iterations of list reversal and tree transformations.
