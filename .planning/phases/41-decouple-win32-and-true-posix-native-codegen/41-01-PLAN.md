<objective>
Decouple Win32-specific APIs from native code generation backends (Cranelift and LLVM), standardize system call abstractions to use POSIX libc (`exit`, `write`, `malloc`) on non-Windows platforms, make the benchmark harness and C baselines cross-platform, and ensure the Linux Docker container compiles and links natively without unresolved Windows kernel32 symbols.

Purpose: Eliminate platform lock-in and enable true cross-platform portability for Linux/macOS and reproducible Docker evaluation.
Output: Refactored `cranelift_backend.rs`, `llvm_backend.rs`, `entry_bench.c`, `linker.rs`, `runner.py`, and verified test suite.
</objective>

  <name>Task 1: Abstract system calls in Cranelift and LLVM native codegen backends (PORT-01)</name>
  <files>src/codegen/cranelift_backend.rs, src/codegen/llvm_backend.rs</files>
  <read_first>src/codegen/cranelift_backend.rs, src/codegen/llvm_backend.rs</read_first>
  <action>
    In `src/codegen/cranelift_backend.rs`:
    1. Replace unconditional declarations of `ExitProcess`, `GetStdHandle`, and `WriteFile` with platform-abstracted runtime signatures:
       - On `#[cfg(target_os = "windows")]`: declare `ExitProcess`, `GetStdHandle`, and `WriteFile` from `kernel32.lib`.
       - On `#[cfg(not(target_os = "windows"))]`: declare standard POSIX libc functions: `exit(i32) -> void` and `write(i32, *const u8, usize) -> isize`.
    2. Abstract runtime print and exit helpers:
       - In `emit_helper_print_str`: on Windows invoke `GetStdHandle(-11)` and `WriteFile`; on non-Windows invoke `write(1, ptr, len)`.
       - In `emit_main_wrapper` / `compile_entry_point`: on Windows emit `mainCRTStartup` calling `ExitProcess(code)`; on non-Windows emit `main` (or retain user `main` returning integer) calling `exit(code)` if entry wrapper is requested.
       - In `emit_panic` / assertion failure: on Windows invoke `GetStdHandle(-12)`, `WriteFile`, and `ExitProcess(101)`; on non-Windows invoke `write(2, msg_addr, msg_len)` and `exit(101)`.
    
    In `src/codegen/llvm_backend.rs`:
    1. In `declare_intrinsics`: conditionally declare `ExitProcess`, `GetStdHandle`, `WriteFile` on `cfg!(target_os = "windows")`, and declare `exit` and `write` on `cfg!(not(target_os = "windows"))`.
    2. In `emit_windows_entry_point`: rename or guard as platform-specific entry point generator: on Windows emit `mainCRTStartup` with `ExitProcess`; on POSIX do not emit `mainCRTStartup`.
    3. In object emission: replace hardcoded `TargetTriple::create("x86_64-pc-windows-msvc")` with target triple derived from `TargetMachine::get_default_triple()` or conditioned on `target_os = "windows"`.
  </action>
  <verify>cargo test --lib codegen</verify>
  <acceptance_criteria>

    - `src/codegen/llvm_backend.rs` does not hardcode `"x86_64-pc-windows-msvc"` unconditionally
    - All tests in `cargo test --tests` pass with zero failures
  </acceptance_criteria>
  <done>Native code generators declare libc primitives on non-Windows and Windows APIs on Windows.</done>

       ```c
       #ifdef _WIN32
       #include <windows.h>
       #include <stdint.h>
       #include <intrin.h>
       #else
       ```

    4. Provide entry point: `mainCRTStartup` for Windows MSVC linker, and `main` for standard Unix/Linux linker calling `extern long long numlang_main(void);` or `extern long long main(void);`.
  </action>
